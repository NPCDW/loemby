## Context
当前应用启动时由 Rust 后端直接检查、下载并安装更新，用户无法选择；设置页“检查更新”同样会立即安装。改为启动时只检查，发现新版本后在前端右下角提示，只有用户点击“立即更新并重启”才下载、安装和重启。

## 实现方案
1. **拆分后端检查与安装**
   - 修改 `src-tauri/src/service/updater_svc.rs`，复用现有 updater 插件、更新源、签名验证和代理配置。
   - 检查接口只返回新版信息（版本号），不下载、不安装；后端缓存检查得到的 `Update`，安装接口消费该已检查更新，避免用户确认后重新检查并安装另一版本。
   - 增加独立更新状态及并发保护，防止启动检查、手动检查和重复点击导致并发安装；失败后释放操作状态，允许重试。
   - 修改 `src-tauri/src/controller/invoke_ctl.rs` 和 `src-tauri/src/lib.rs`，注册检查与安装命令、初始化更新状态；保留插件注册，移除 setup 中直接更新的异步任务。
2. **统一前端更新提醒**
   - 修改 `src/api/invokeApi.ts`，分别封装检查与安装接口及返回类型，复用现有 `restartApp()`。
   - 改造 `src/util/updater_util.ts`，复用 `ElNotification` / `ElButton` 实现统一提示：右下角显示“发现新版本”和版本号，按钮为“立即更新并重启”“下次再说”；提示不自动消失。
   - 点击立即更新后显示 loading，并禁用重复操作及关闭；安装失败显示明确错误，恢复按钮以便重试，不重启应用。
   - 安装成功后，macOS/Linux 调用现有重启命令；Windows 沿用 updater 安装器自身的退出、安装和重新启动行为。
   - 点击“下次再说”或关闭提示仅关闭本次提醒，不下载、不安装；下次启动重新检查，仍允许设置页主动检查。重复检查不叠加多个更新提示。
3. **接入启动及手动入口**
   - 在 `src/main.ts` 的前端挂载后发起一次非阻塞检查，避免后端事件早于前端监听导致提醒丢失；无更新时保持安静，自动检查失败只记录错误，不打断启动。
   - 修改 `src/page/Setting.vue` 的 `checkUpdate()`，复用相同检查与提醒逻辑，不再直接安装；保留按钮 loading，无新版提示“已经是最新版本”，手动检查失败显示错误。
   - 只修改更新相关代码，不覆盖当前其他未提交改动，不新增依赖、不改发布配置。

## 验证
- 前端运行 `pnpm exec vue-tsc --noEmit --incremental false`；执行 Rust 编译检查（先核对 `build.rs` 的版本同步行为，避免意外改写版本文件）。
- 用 mock 更新响应验证 UI：右下角位置、按钮文案、持久显示、推迟/关闭、重复检查去重、更新中的 loading、失败后恢复及重试。
- 验证“无新版”“检查失败”“有新版但推迟”均不会调用下载、安装或重启；仅点击立即更新后执行安装，且安装失败不会重启。
- GUI 联调使用隔离测试数据或 mock，不在当前运行环境实际安装生产更新；真实安装和跨平台重启需在隔离的桌面测试环境验收。未能执行的检查会明确说明。
