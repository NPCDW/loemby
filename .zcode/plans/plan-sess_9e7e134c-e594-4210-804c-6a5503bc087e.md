## Context
Trakt、Simkl、YamTrack 及「应用数据代理」目前只有正向代理选项，无法选择已有的反代服务器。目标是补齐这四处配置及其实际 HTTP 请求，并提供全局请求代理覆盖检查结果。

按你选择的范围：**本次不修改媒体直链、媒体重定向或 HLS 播放逻辑**，这些遗漏只记录位置和影响。

## 实施方案

### 1. 增加四处反代设置
修改 `src/page/Setting.vue`：
- 为 Trakt、Simkl、YamTrack 和应用数据分别增加「反向代理」选择框，复用现有 `reverseProxyServers` 列表及 `configValueChange()`。
- 新增配置键：`trakt_reverse_proxy_id`、`simkl_reverse_proxy_id`、`yamtrack_reverse_proxy_id`、`app_reverse_proxy_id`。
- 默认「不使用反代」，保留旧版正向代理选择及默认继承行为；无需数据库迁移。
- 将原代理标签明确为「正向代理」。两者独立选择，不自动清空正向代理，允许“正向代理 → 反代服务器 → 目标服务”。
- 提示：浏览器授权页面使用浏览器自己的网络设置；反代会接触令牌、Webhook 地址等敏感数据，请使用可信服务器。

### 2. 复用现有反代机制，补齐追踪及图标请求
在 `src-tauri/src/mapper/reverse_proxy_server_mapper.rs` 增加通用目标 URL 处理函数，复用 `get_reverse_proxy_url()` 和 `normalize_url()`。
- 沿用现有协议：`反代前缀 + 完整原始 HTTP(S) URL`，不是替换 API 域名。
- 未配置反代时保持原 URL；保留路径、查询参数和编码，避免同一前缀重复拼接。
- 仅处理远程请求目标，不改写 OAuth 的本地回调地址、请求体中的 `redirect_uri` 或应用内部 IPC。

接入以下请求：
- `src-tauri/src/service/trakt_http_svc.rs`：Token 交换、Token 刷新、用户信息、开始/停止同步。
- `src-tauri/src/service/simkl_http_svc.rs`：Token 交换、用户信息、开始/暂停/停止同步。
- `src-tauri/src/service/yamtrack_http_svc.rs`：自定义 Webhook。
- `src-tauri/src/service/app_http_svc.rs`：图标库 JSON。
- `src-tauri/src/service/axum_svc.rs`：仅应用图标图片入口，不改 Emby 媒体转发逻辑。

正向代理仍使用 `proxy_server_mapper::get_app_proxy_url()` 和现有 HTTP 连接池；反代设置在请求时读取缓存，修改后对后续请求生效。

### 3. 完整覆盖应用更新的两阶段请求
修改 `src-tauri/src/service/updater_svc.rs`：
- 从现有 Tauri updater 配置读取更新地址，按 `app_reverse_proxy_id` 改写检查端点，不额外硬编码一份发布地址。
- 更新检查与安装包下载均支持应用正向代理和反代，不能只代理 `latest.json`。
- 保留原始安装包 URL，在安装前根据当前配置生成下载地址和正向代理设置，避免待安装对象沿用过期代理或重复添加反代前缀。
- 保持已有版本确认、签名校验和用户确认后安装流程；不更换 updater、不绕过签名校验。

### 4. 记录全局检查结果与边界
补充 `docs/reverse.md` 的使用说明、代理覆盖表和未修复项：
- Emby API、海报、字幕等已有正向/反代支持；应用数据代理并非所有服务的统一策略，追踪与 Emby 有独立选择。
- 媒体绝对直链、手动重定向、HLS 相对链接/密钥链接存在遗漏，本次不改。
- API/图片/updater 的自动重定向依赖反代服务器正确改写 `Location`；当前服务端示例已有此要求，不声称客户端已补齐所有重定向。
- “不使用代理”目前仍可能继承系统/环境代理，本次不改变全局 HTTP 客户端语义。
- 系统浏览器授权页及外部链接、用户自定义 mpv/FFmpeg 网络行为、构建和 CI 下载不受应用内代理设置控制；本地 Axum 和 OAuth 回调不应套用反代。
- 本次不顺带修改发现的其他同步或授权逻辑问题。

## 验证
- 添加 Rust URL 路由及更新下载路由回归测试：无反代、有效反代、规范化尾斜杠、已有前缀、编码/查询参数保留，以及待安装更新在代理配置变化后正确生成下载目标。
- 检查全部追踪请求和应用数据请求均使用对应设置，包括 Trakt 刷新、Simkl 暂停及更新包下载；正向代理继承逻辑保持不变。
- 使用本地模拟 HTTP 端点验证请求路径、方法、请求体和必要请求头，不向真实追踪服务发送记录，不执行真实更新安装。
- 运行前端类型检查/构建和 Rust 检查/测试；若环境依赖缺失，明确报告未执行或失败的检查。
- 验证四处选择框的默认值、保存及重新读取；可运行前端时用浏览器检查界面。真实账户授权和真实反代连通性需使用你的服务环境，未实测会明确说明。
